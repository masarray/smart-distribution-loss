# Engineering Audit — Smart Distribution Loss

## Verdict

The repository is already a strong **Demo / Proof of Concept**, not a production DMS. Its strongest point is that the headline loss results are generated by a real three-phase Pandapower physics workflow rather than scripted dashboard values.

### Current maturity

- **POC / technical demo:** strong
- **Engineering transparency:** strong
- **UI storytelling:** strong
- **Production utility deployment:** not yet the scope
- **Standards-certified drawing package:** not yet claimed

## What is already technically good

1. The project separates a physics engine from a smart estimation/calibration layer.
2. The network workflow uses `pandapower.runpp_3ph()` for unbalanced three-phase calculation.
3. Synthetic Ground Truth is generated deterministically.
4. Field-data degradation is controlled and reproducible.
5. Conventional and Smart models are both run through physics calculations.
6. Calibration is staged and bounded instead of being a black-box AI estimator.
7. The P3 workflow uses calibration and hold-out intervals instead of validating only on the data used for fitting.
8. Gate checks expose convergence, residual improvement, phase fit, voltage plausibility, and hidden-truth validation.
9. The UI exposes observability, calibration stages, residual/error metrics, and parameters intentionally held from calibration.

## Important issues found and corrected in this package

### 1. Site-builder / SSR coupling

The original repository was coupled to a site-builder-specific TanStack Start configuration and SSR/server files. That made a static GitHub Pages deployment unnecessarily fragile.

**Correction:** converted to a normal static **Vite + React** application. Site-builder metadata, telemetry/error bridge, SSR entry files, TanStack Start, Nitro/Cloudflare assumptions, and builder-specific Vite configuration were removed.

### 2. GitHub Pages sub-path bug

The original browser worker was created with an absolute root URL:

```ts
new Worker("/sdl-worker.js")
```

That breaks on project Pages URLs such as `https://user.github.io/repository/`.

**Correction:** the worker now uses `import.meta.env.BASE_URL`. Vite also derives the Pages base path automatically from `GITHUB_REPOSITORY` during Actions builds.

### 3. Single-line diagram engineering convention

The original SLD mixed a vertical bus segment, horizontal feeder, simplified device boxes, and customer rectangles in a way that looked good visually but was closer to an infographic than an engineering single-line diagram.

**Correction:** the revised SLD uses a clearer electrical hierarchy:

`GI source → incoming CB → 20 kV busbar → outgoing CB/meter/load branches → distribution transformer → LV main CB → 0.4 kV busbar → JTR outgoing breakers → customer groups`

Busbars are visually distinct from conductors, switchgear has equipment tags, metering points are explicit, the transformer is shown as a two-winding transformer, and the LV bus is identified as `3Φ4W`.

The SVG is intentionally described as **IEC-style / standards-aligned**, not as a licensed IEC 60617 symbol-library reproduction.

### 4. Duplicate MV result presented as a second asset

The previous UI used the same Spot-MV simulation result for both `Spot MV` and `Pelanggan TM`. This could make the ledger look as though two independent asset calculations existed when only one MV proof was calculated.

**Correction:** `Pelanggan TM` remains visible as a measurement/reference object, but its independent loss KPI is no longer fabricated from the Spot-MV result. It is marked `REFERENCE ONLY` until an independent TM model is implemented.

### 5. Ground-Truth boundary for Q measurement

P3 previously created its noisy feeder-Q measurement by reading the hidden P1 structure inside the calibration module. The value was measurement-like, but the architectural boundary was weaker than the design intent.

**Correction:** feeder-Q measurement synthesis/noise now belongs to P2's data-quality/measurement layer. P3 consumes the degraded measurement channel and does not read hidden P1 truth before final validation.

### 6. Unit consistency

The Spot-MV daily loss result was shown once as `kWh/hr` although the engine result is an integrated daily `loss_kwh` value.

**Correction:** the SLD now displays `kWh/hari`.

## Remaining work before calling it an engineering-grade product

1. **Independent Pelanggan-TM model** — build a separate model/result rather than a reference node.
2. **External benchmark** — run canonical regression against selected SimBench networks after the synthetic scenario is stable.
3. **Formal symbol verification** — perform a symbol-by-symbol review against the licensed IEC 60617 database and the utility's own drawing standard before claiming full compliance.
4. **Reference designation policy** — decide whether tags follow utility naming or a formal IEC/ISO 81346 scheme and apply it consistently across UI, JSON, and exported reports.
5. **Automated browser regression** — CI should eventually execute the Pyodide/Pandapower scenario and assert the P0–P3 gates, not only build the frontend.
6. **License decision** — choose the repository license and document third-party attribution before public open-source release.
7. **Performance packaging** — first simulation currently downloads and initializes Pyodide plus Pandapower. Consider prebuilt/cache strategy or a separate local FastAPI backend for larger networks.
8. **Export/provenance UX** — expose scenario JSON / CSV result export and parameter provenance more prominently to complete the PRD's explainability goals.

## Deployment readiness

The package includes:

- pure Vite static build;
- automatic GitHub Pages base-path handling;
- relative worker/engine loading compatible with repository sub-paths;
- `.nojekyll`;
- `.github/workflows/deploy-pages.yml`;
- no server runtime requirement.

After pushing to `main`, set **Settings → Pages → Source → GitHub Actions**.
